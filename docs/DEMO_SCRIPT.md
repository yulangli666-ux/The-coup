# 项目演示脚本

这份文档适合你在 GitHub、面试、老师答辩或朋友试玩时使用。

## 一、演示前准备

- 两台手机，或一台手机加一个开发者工具
- 云函数已全部上传
- 数据库集合已创建
- 至少准备 2 个测试账号
- 如需展示人机补位，提前说明该功能是为了低人数测试与单人验证准备的

## 二、推荐演示顺序

### 1. 展示大厅页

你可以这样介绍：

`这是项目首页，支持玩家自动登录、修改昵称、创建房间、输入 4 位房间码加入房间，也可以快速加入等待中的房间。`

重点展示：

- 玩家昵称
- 创建房间
- 加入房间
- 快速加入
- 历史战绩入口
- 规则说明入口

### 2. 展示等待房间

你可以这样介绍：

`进入等待房间后，房主可以看到唯一房间码，并控制本局的回合时长，还可以添加机器人补位，满足低人数测试和单人验证。`

重点展示：

- 房间码
- 玩家列表
- 房主身份
- 回合时长设置
- 添加人机

### 3. 展示开始对局

你可以这样介绍：

`开始游戏后，房间状态会实时同步到所有玩家端。页面中间是当前回合与行为日志，底部是当前玩家的手牌与操作区。`

重点展示：

- 左右玩家席位
- 中央日志
- 当前回合
- 手牌显示
- 行动按钮

### 4. 展示核心规则链路

建议至少演示以下几种：

- 收入
- 公爵拿 3 金
- 外国援助与阻挡
- 杀手暗杀
- 质疑
- 大使换牌
- 弃牌

你可以这样介绍：

`项目的关键不只是页面，而是把桌游里的宣称、质疑、阻挡、弃牌和换牌流程都串成了完整状态机，并放在云函数中统一结算。`

### 5. 展示聊天与表情

你可以这样介绍：

`除了核心对局逻辑，项目还做了轻量互动能力，包括表情和文字消息，能增强多人游玩体验。`

### 6. 展示历史战绩

你可以这样介绍：

`每局结束后会保存历史战绩，方便回顾对局结果，也利于后续扩展战报系统。`

### 7. 展示人机补位

你可以这样介绍：

`为了方便测试和低人数开局，项目加入了机器人补位。机器人可以参与部分基础决策，让联机测试不完全依赖真人数量。`

## 三、适合放进 README 的演示摘要

可直接复制：

`演示流程包括：首页登录与房间创建、4 位房间码邀请、等待房间设置、人机补位、多人实时对局、质疑与阻挡结算、大使换牌、表情聊天、历史战绩查看。`

## 四、录屏建议

### 推荐录制 1 段 2 到 4 分钟视频

视频内容建议按这个顺序：

1. 首页进入
2. 创建房间
3. 第二名玩家加入
4. 房主开始游戏
5. 演示 2 到 3 个关键行动
6. 演示一次质疑或阻挡
7. 演示一次弃牌或换牌
8. 展示历史战绩
